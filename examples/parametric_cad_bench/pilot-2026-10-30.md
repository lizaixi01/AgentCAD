# Parametric CAD Bench V3 pilot — 2026-10-30

AgentCAD can produce the native PartDesign models required by V3: **6/6 tasks
submitted valid editable parts and received scores**, with no timeouts or
out-of-protocol tool calls. The six-task mean reward was **55.43/100**. One
creation task was almost exact; complex profiles, edits and drawing
reconstruction still lost substantial geometry credit.

This evaluates **Codex + gpt-6.1-sol + AgentCAD**, rather than AgentCAD in
isolation. It is a local pilot with a shorter time budget and a different
FreeCAD build, **not a leaderboard result**. The six-task mean does not estimate
the 100-task leaderboard reliably.

## What worked, and where accuracy was lost

The linkage rod passed all 11 specification checks and scored 0.999995 on
geometry. Native operations are sufficient for at least this combination of
cylindrical stock, trimmed lugs, transverse cuts and pin holes. All eight
submitted files passed the validator's native feature-tree/body gates; the
adapter did not turn baked shapes into nominally native parts.

Both edit bases were near exact. The weaker target scores show why the two
phases must be measured separately. The camera target scored 0.256 on geometry
and 0.9 on specifications; the rail target scored 0.500 and 0.9. Post-run
specification diagnostics could not find final-geometry witnesses for the
camera's `rail_channel_inner_step_height` or the rail bracket's
`vertical_adjustment_slot_width`. These are scorer findings, not proof that the
features are entirely absent.

The clamp had a valid solid and only a 0.631% volume difference, yet its geometry
score was 0.127. Five checks disagreed and three were not found. Examples include
contact angles, a negative vertical angle and small 0.46 mm divider/inset
dimensions modeled as 0.47 mm. Neither a valid solid nor approximately correct
volume certifies an accurate profile. The V3 specification score penalizes
failed checks using a failure budget of 10; its 0.2 score is not the raw fraction
of checks that matched (28/36).

The drawing reconstructions scored 0.179 and 0.356 on geometry, despite 35/37
and 12/12 matching specification checks. Reading principal dimensions and
constructing a recognizable solid was achievable; faithfully reconstructing
local contours and relative feature placement remained harder. No hidden
dimensions or grader feedback were provided during modeling.

Tool traces also show avoidable friction: requests for an unsupported
`constrain` operation, expressions in polygon coordinates/arc radii where only
numbers are accepted, and a rejected `deg` unit. Agents recovered and submitted
all tasks, but more explicit discoverability, expression support and constraint
control would reduce detours. This pilot has no direct-FreeCAD control run, so
it does not establish which errors belong to the model versus the interface.

## Run conditions and audit trail

- Dataset: `gnucleus-ai/cad-bench@v3`, downloaded with Harbor 0.23.0; 30 creation,
  30 create-and-edit and 40 drawing tasks. Two tasks per category were sampled
  without replacement from sorted IDs, using one random generator with seed 42,
  before any run. There was no score-based selection.
- Runtime code: `945e6c649de6db9d4cafd8069f2f8d1a5b845d44`; executed adapter:
  `cc72d50`. Exact executed Python-file hashes are in the ledger. Subsequent
  changes add score-contract normalization, stage auditing and incremental
  summarization; they did not change the six model executions.
- Agent: Codex CLI 0.163.0, `gpt-6.1-sol`, requested effort `xhigh`, existing
  ChatGPT login. Effective effort was not emitted in the JSON trace. Token
  usage is recorded; dollar cost was not measured.
- Windows build 26200; Python 3.11.16; AgentCAD runtime 0.1.0; MCP 1.30.0;
  FreeCAD 1.1.4 / OCCT 7.8.1; validator 0.6.0, default v2 scorer.
- Each task had a fresh Codex process, workspace and MCP server; two tasks ran
  concurrently, with a 900-second limit each. Scripts, shell and web search were
  disabled and other configured MCP servers were excluded. Only public
  instructions and task PNGs were staged; CAD tools were confined to their root.
  This is local tool isolation, not the official container/network boundary.
- A file-only adapter froze `part.FCStd` into `answer.FCStd`, or into base/edit
  outputs at the two edit stages. It supplied no modeling or grader knowledge.
  The requested `answer.py` was explicitly omitted for this pilot.
- Each completed task was scored once with its unmodified `tests/run_scorer.py`,
  outside the agent's workspace. A separate reference-versus-itself preflight
  scored 1.000; it is an infrastructure control, excluded from the six results.
- The drawing scorer's diagnostic sidecar uses `reward`, whereas text/edit
  sidecars use `score`. The adapter was corrected to read the authoritative
  single-key `reward.json`. The existing first drawing result was normalized
  from its saved reward; neither its model attempt nor its scorer was rerun.
- Harbor's registry returned the published V3 digest
  `sha256:8a786725d3648a76282fc5868df06da3d5e00d603f283573a53430803465d78a`.
  The complete local bundle digest was not independently verified before the
  run; instruction/task metadata hashes were frozen, and input PNG hashes were
  checked against the untouched source bundle afterwards.

## Remaining work before entering V3

The [official run protocol](https://cadbench.ai/benchmark) requires a complete
100-task public Harbor job, the frozen environment, one attempt per task, no
retries and a 9,000-second task limit. The following work remains:

1. **Package the agent for Harbor.** Install AgentCAD in the official FreeCAD
   1.1.0 environment, keep the verifier separate, enforce `/app` scope and
   provider-only networking, and verify the pinned dataset/task digests before
   starting. The local machine's Docker daemon was unavailable; its remote
   Docker context also failed SSH host verification. Neither was changed.
2. **Meet the original output contract.** Export a replayable `answer.py` from
   successful native operations, including base and edit stage outputs derived
   from `__file__`. The current file-copy adapter is a pilot convenience. The
   existing baked CadQuery/ScriptSolid route cannot substitute for V3's native
   PartDesign feature tree.
3. **Strengthen geometric feedback.** Check local separations, hole placement,
   exact arcs/tangencies and small dimensions against the public task before
   submission. Improve operation discovery and consider parametric polygon/arc
   coordinates or a sketch-constraint interface. Measure these changes on a
   separately declared run while retaining this baseline.
4. **Produce the full evidence package.** Capture complete ATIF trajectories,
   effective effort, authentication/cost metadata, all native outputs and every
   failure; run all 100 tasks under the official budget and publish the job.
   Confirm the V3 submission-manifest format with maintainers: the
   [submission repository](https://github.com/gNucleus-AI/cad-bench-submission)
   still documents V2, which the current V3 run page explicitly distinguishes.

The useful next engineering step is the Harbor wrapper and native-operation
replay exporter, followed by a geometry-feedback improvement pass. This pilot
establishes basic native-file compatibility. The next measurements should track
local geometry accuracy and completion of the full submission protocol.
