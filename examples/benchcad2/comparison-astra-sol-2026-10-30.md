# BenchCAD 2 公开样例：GPT-6 Astra max 与 GPT-6.1 Sol max

**原始九次尝试的六类等权均分：Astra 56.79/100，Sol 53.45/100，Astra 高 3.34 分。**
主要差距来自供给零件装配和混合装配。Astra 有一题在连接异常时退出、未提交，按预设规则计零；
额外一次连接恢复试验也未提交，完整保留，未替换主表。

两轮使用相同 AgentCAD `25835161de291daa4035e81a7e8ba501e1474a63`，单题上限
3,600 秒、100 次 MCP 调用，最多两题并行，提交后单进程离线评分。
主对比严格采用每个模型、每题的第一次尝试，原 Sol 记录不变。

这是 **9 个公开开发样例、6 类任务**，采用自定义 Codex + AgentCAD 流程；
没有使用需要权限的 100 题 Core，不能据此与官方排行榜排名。
T6 是模型通过 JSON 适配器推理电路连接；T2 和 T4/T5 的装配位置由模型及适配器处理。
六类总分包含这些能力，不能单独代表 CAD 内核性能。

## 差异在哪里

- **T2 装配是主要分差来源。** 两边的 26/36 个实例数量正确，供给几何项为 1.0，
  提交检查均无失败。Astra 的定位项分别为 0.387411、0.682737，Sol 为 0.206806、
  0.028940。Astra 的整体对齐 IoU 为 0.9965、1.0；逐类定位分仍低于满分。
- **T5 的提升同样主要来自定位。** 两边五种图纸新零件的均分几乎相同：
  Astra 0.9977756、Sol 0.9979226；该均分只计新建零件。装配项为 0.904607 对
  0.592858，相乘得到 90.26 对 59.16。两边均为 25 个实例，提交检查无失败。
- **单件建模没有一致优势。** T1 几何项接近，Astra 的拓扑项为 0.701972、Sol 为 1.0；
  参考拓扑计数 `[1,30,0]`，Astra 为 `[1,36,0]`。T3/case1 两边拓扑项均为 1.0，
  Astra 的几何项较低；T3/case2 的几何和拓扑项均有改善，拓扑项从 0.111111 到 0.25。
  两道 T3 合计只有 0.65 分的差距。
- **复杂视图重建仍低分。** T4 的零件项为 0.452089 对 0.426744，装配项为
  0.358756 对 0.320725；两者相乘后仍只有 16.22 对 13.69。两边九个实例均已提交，
  提交检查无失败，误差同时存在于单件几何和定位。
- **T6/case2 的 Astra 零分表示未交付。** 模型未提交连接图，电路答案准确性未知。
  T6/case1 两边均为 100；这类任务没有使用 AgentCAD 原理图引擎。

## 连接失败与补充试验

T6/case2 的第一次尝试在五次连接重试后回退到 HTTP，最终以 `Bad Request` / `turn.failed`
退出。按开始前的无提交规则记零，保留在主表。随后依据原协议显式进行一次
`--retry-infra` 补充试验，开始前已固定“不替换首次结果、不按成绩挑选”的处理规则。
补充试验期间 HTTP 回退后曾继续读取照片，最后仍以相同错误退出。

| 尝试 | 秒 | MCP 调用 | MCP 工具错误 | 连接重试 | 退出 | 提交 |
|---|---:|---:|---:|---:|---|---|
| 首次（计入主表） | 371.4 | 17 | 0 | 5 | agent_error / 1 | 无 |
| 补充（单列） | 1,257.2 | 17 | 0 | 7 | agent_error / 1 | 无 |

两次都未耗尽单题时间或调用预算。终端错误未提供足够信息确认根因；
两次均在 17 次照片读取后结束是可复查的现象，不能据此断言具体的图片或上下文限制。
本轮没有改输入、模型参数或工具来重新生成成绩。补充试验没有产生有效答案，合计分数不变。

## 一致性与复核

- 实际运行元数据的唯一差异是 `model`：`gpt-6.1-sol` → `gpt-6-astra`。
  AgentCAD、运行器、适配器、提示与预算均固定为原 Sol 快照。
- 9 份提示相同，130 个暂存输入文件逐字节相同，9 条命令仅模型名及必要本地路径不同；
  补充尝试也检查了同样的提示、输入与路径归一化后的命令。
- BenchCAD 固定为 v2.1 / `70b7aaeb3a031851d058252e4ebe4ed30ca41f77`，
  144 个输入及参考文件匹配官方清单；九个 1.0 标准答案检查因数据、源码和评分协议未变而复用。
- 评分采用原来的 `BENCHCAD_MESH_GUARD=0`、数值库线程 1。该官方模式保留度量计算，
  没有 POSIX 网格子进程的 CPU 隔离及 BREP 序列化往返，外层仍有评分时限。
- Python 3.11.16、CadQuery 2.8.0、FreeCAD 1.1.4、Codex CLI 0.163.0，已有 ChatGPT 登录，
  未使用 API key。参考答案和评分源码不进入模型工作区，评分不反馈给模型。
- 首次提交封存；未提交计零，评分器故障单独记录。没有给耗尽预算的题补发预算。
- 测量前 24 项适配层测试及原生建模/STEP 导出检查通过。归档后复核 142 项原始记录哈希。

归档后在当前主线 `0b93e9b` 上通过 **683 项回归测试**（620.71 秒）及生成文档一致性检查。
为避免占用共享 AutoCAD，排除 `tests/test_autocad_live.py` 和 `tests/test_native_delivery.py`；
本机 FreeCAD 检查仍运行。该主线集成检查不属于固定快照的模型测量。

## 复现

从 `2583516` 创建独立工作区，安装上述依赖，按 [原 README](README.md#reproduce) 配置环境、
`$benchSource`、`$benchPython`。当前主分支已有后续工具和提示变化，直接运行不属于这组历史对照。
在历史工作区只覆盖模型常量：

```powershell
function Invoke-AstraBench {
    .venv\Scripts\python -c "import importlib.util; s=importlib.util.spec_from_file_location('bench','examples/benchcad2/run.py'); m=importlib.util.module_from_spec(s); s.loader.exec_module(m); m.MODEL='gpt-6-astra'; m.main()" @args
}

# 全新输出目录，其他环境沿用原 Sol 配置。
$astraOutput = '<new output directory>'
Invoke-AstraBench oracle --bench-source $benchSource --bench-python $benchPython --out $astraOutput
Invoke-AstraBench run --bench-source $benchSource --bench-python $benchPython --out $astraOutput --timeout 3600 --calls 100 --jobs 2 --resume
Invoke-AstraBench score --bench-source $benchSource --bench-python $benchPython --out $astraOutput --timeout 3600 --jobs 1 --resume
```

实际启动器还检查了源提交、文件哈希、CLI 版本和原 Sol 元数据，并预先冻结输入、提示与命令对照。
完整启动器、原始日志、图像及答案保留于
`D:\Projects\AgentCAD-output\benchcad2-astra-max-20261030`；含图像日志和 STEP 答案不入库。
原 Sol 目录为 `D:\Projects\AgentCAD-output\benchcad2-sol-max-20261030-final`。

每个模型九次首次尝试足以描述本轮差异，样例规模与单次采样仍不足以断言一般任务上的模型优劣。
