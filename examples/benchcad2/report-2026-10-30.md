# BenchCAD 2 公开样例评测：GPT-6.1 Sol / max

本次按用户选择，测试 BenchCAD 2 仓库附带的 **9 个公开开发样例，覆盖 6 类任务**。
Core 的 100 题需要另行获得权限，本次没有使用。样例数量很小，而且采用了
Codex + AgentCAD 的自定义 MCP 流程，因此不能与官方排行榜的分数直接比较。

测量对象固定为 AgentCAD `2583516`。复现本轮应从该提交创建独立工作区；
主分支后续合入的功能变更应作为新的实验记录。

## 能力边界与评分

T1（工程图建零件）和 T3（多视图建零件）直接使用 AgentCAD 的实体建模能力。
T4/T5 的新零件同样通过 AgentCAD 创建，装配位置由模型给出、适配器保存。
T2 使用供给零件，主要测试模型的装配推理；AgentCAD 尚无原生装配引擎。
T6 是模型通过 JSON 适配器完成电路连接推理，AgentCAD 尚无原理图引擎。
因此，六类任务的合计分数不代表 CAD 内核本身的性能。

评分使用固定版本的官方 `score_case`：T1/T3 为 `part_v1`，T2 为 `asm_v1`，
T4/T5 为 `avg_part × asm_v1`，T6 为 `ecad_v2`。合计取六类任务均分的平均值，
避免两道样例的类别占更高权重。只有九题全部评分且版本与已验证参考答案一致时，
才计算合计分数。

## 逐题观察

- **T1 / case1：78.22/100。** 本题允许旋转对齐；官方 24 个旋转对齐后的
  IoU 为 0.762406，归一化几何项为 0.727757，拓扑项为 1.0。
  说明拓扑项满足参考，并不意味着局部几何已经完全吻合。
  模型实际通过 AgentCAD 执行 CadQuery 脚本，中间两次几何修订触发
  `Bnd_Box is void`，被拒绝保存，修正后继续完成。
  本题没有原生 PartDesign 特征树的验收要求。
- **T2 / case1：20.68/100。** 26 个实例数量正确，供给零件几何项为 1.0，
  没有缺少或增加零件类型，提交检查没有失败。但对齐后的整体 IoU 为 0.9687，
  逐类零件的 `asm_v1` 仅为 0.206806。总外形重叠不能代替各类零件的位置和朝向
  准确性检查；本题的原始未对齐 IoU 为 0.1249，也不能混作头部成绩。
- **T2 / case2：2.89/100。** 36 个实例数量正确，供给几何项为 1.0，提交检查
  没有失败，但对齐后的整体 IoU 为 0.4421，`asm_v1` 为 0.02894。
  两道 T2 样例均分为 11.79/100；这反映本轮模型与装配适配器组合的定位表现，
  不能解释成尚未实现的原生装配引擎成绩。
- **T3 / case1：69.68/100。** 按本题 `pinned / expert-fit` 协议，几何 IoU
  为 0.757359，归一化几何项为 0.621024，拓扑项为 1.0。
  69 次调用中有 12 次错误：参数不兼容 1 次、脚本子进程访问异常 2 次、
  脚本超时 2 次、原生特征操作失败 2 次、STEP 导出一致性检查失败 5 次。
  这些错误没有终止 MCP 服务；模型最终仍显式提交了 STEP，评分读取的是该提交文件。
- **T3 / case2：47.23/100。** 几何 IoU 为 0.699013，归一化几何项为 0.562652，
  拓扑项仅为 0.111111。55 次工具调用均成功，仍存在参考拓扑差异。
  两道 T3 样例均分为 58.46/100；调用成功、实体有效和形状准确是不同验收层次。
- **T4 / case1：13.69/100。** 七种新零件、九个实例均已提交，提交检查没有失败。
  平均零件项为 0.426744，装配项为 0.320725，两者相乘得到最终分数。
  本题同时存在单件几何和装配定位的误差；完成文件生成不能代替准确性验收。
- **T5 / case1：59.16/100。** 五种图纸新零件的平均得分为 0.997923；
  该平均值只计新建零件，不含十六种供给零件。装配项为 0.592858，
  两者相乘为最终分数。25 个实例数量正确，提交检查没有失败，
  本题主要剩余误差来自装配位置与朝向。53 次工具调用中有一次脚本被拒绝。
- **T6 / case1：100/100。** 模型读取照片并通过 JSON 适配器提交连接图，14 次
  工具调用、约 3.7 分钟完成。该题没有使用 CAD 建模功能，不能作为原理图引擎的验收。
- **T6 / case2：98.80/100。** 40 个组件全部匹配，173 条端子与网络关联中匹配
  172 条，未触发致命电源故障，搜索已完成且不是下界。37 次调用中有一次空路径读取
  错误。两道 T6 公开样例均分为 99.40/100。

## 运行校验与集成试验

- 144 个输入及参考文件全部匹配官方 SHA-256 清单；BenchCAD 使用不转换换行的独立副本。
- 九题标准答案均得到 1.0，评分器及其数据已通过自检。
- Windows 下官方 POSIX 网格子进程不可用，因此采用官方提供的
  `BENCHCAD_MESH_GUARD=0` 模式。几何度量相同，但没有该子进程的 CPU 隔离和
  BREP 序列化往返，外层仍有评分时限。数值计算线程固定为 1。
- 486 项回归测试通过（不运行会占用共享 AutoCAD 的实机测试）；之后的预览修复
  通过全部 24 项适配层测试，并以实际 26 零件装配验证四视图预览。
- 主分支集成后的 `02ba8c8` 通过 539 项回归测试（仍排除实机 AutoCAD），包括全部
  25 项适配层测试。当前可复用入口固定完整工具目录，并采用适合新版比较器的提示；
  这些集成修改不属于前述固定快照的模型测量。
- 历史实现通过[独立审查](https://github.com/lizaixi01/AgentCAD/pull/34#issuecomment-6517248476)；
  集成实现与测量记录通过[最终独立审查](https://github.com/lizaixi01/AgentCAD/pull/34#issuecomment-6520647465)，
  其中 45 个归档哈希、144 个清单文件及全部逐题记录均已独立复核。

正式运行前有两次中止的集成试验，均保留原始记录，不计入最终成绩，也没有赋予性能分数：
第一次在 `benchcad2-sol-max-20261030`，因主机内存压力导致 CAD 导入及预览失败；
第二次在 `benchcad2-sol-max-20261030-dev9`，因预览适配器的变换调用拒绝精确旋转矩阵，
在两道活动题均未提交时停止。该接口错误已复现并修复，供给几何和提交矩阵保持不变。

详细接口、复现命令和与官方流程的差异见 [README](README.md)。
