# 对比实验（难题版）：Agent 用 AgentCAD vs Agent 直接写代码

日期：2026-10-27。接着[简单任务的对比](comparison-code-vs-agentcad.md)，换成三道更接近真实工作的题，两组各跑 3 次。

**结论先说**：

- **正确性**：多轮修订（含撤回）和批量出图，两组 3 次全对；**真实 DWG 改图，直接写代码 3/3 全对，AgentCAD 0/3**。AgentCAD 只处理模型空间，没有改到图纸里真正用来打印的那张图纸布局，交付的图纸前后矛盾。
- **速度**：AgentCAD 快 2–3.5 倍。
- **成本**：直接写代码的模型输出量是 AgentCAD 的 1.7–3.4 倍；输入量互有高低（H1、H3 少 20–40%，H2 多 50%）。
- **撤回**：两组都做对了。AgentCAD 用的是内置的历史和检查点；直接写代码的 Agent 在每次运行中都自己重新搭了一套"改前备份 + 改动记录 + 逐字节核对"。
- **更新（2026-10-28）**：AgentCAD 补上图纸空间布局等支持后，重跑真实 DWG 改图，**3/3 全对**，平均 3.4 分钟（直接写代码 9.7 分钟）。见文末"改进之后"。

## 三道题

| 题 | 内容 | 难在哪 |
|---|---|---|
| H1 多轮修订 | 同事画的安装板图（120×80、4×Ø10、真实尺寸标注、标题栏块属性、技术要求、带剖面线的客户标识），连续 5 轮修改，**每轮是一个新会话，不记得之前的对话**：① 加宽到 150，右侧孔随动 ② 孔改 Ø12 ③ 加中心孔 Ø30 ④ **撤回第 2 轮**（不告诉旧值），保留 ①③ ⑤ 改标题栏版本号为 C、加修订说明 | 非线性撤回；每轮只能改该改的；别人的内容要原样保留 |
| H2 真实 DWG 改图 | AutoCAD 自带样例 VW252-02-0142（真实钣金零件，84 个孔、7 种孔径）：Ø10.2→Ø10.5（18 个），Ø25→Ø26（6 个），给两个 Ø40 孔加标注，加修订文字，其余不许动，交付 DWG | 真实图纸结构；DWG 格式；"其余不许动" |
| H3 批量出图 | 按一张 12 行的参数表生成 12 张法兰图，其中 2 行参数在几何上不成立（螺栓孔超出外圆 1 mm；螺栓孔互相重叠） | 批量；识别并拒绝无效参数 |

两组的 Agent、推理强度、任务文字完全相同。A 组只能用 AgentCAD 的 MCP 工具；B 组只能写 Python（环境里只有 ezdxf），工作目录在仓库外。

H2 的一处不对称：B 组在 Codex 沙箱里启动不了 AutoCAD（报 "Problem with setting up current profile"），给它完全权限又被安全检查拦下。按你的决定，由我用 AutoCAD 把 DWG 转成 DXF 交给 B，B 改完的 DXF 再由我用 AutoCAD 转回 DWG，按同样标准评分。所以 B 的 H2 成绩不包含"自己处理 DWG"这一步。

## 评分方法

- 中立评分脚本（[grade_hard.py](../examples/trials/hard/grade_hard.py)），只用 ezdxf 读文件，不用 AgentCAD 自己的验证器。
- H1 对**每一轮**之后的图纸单独评分（运行器在每轮后把图纸复制到 Agent 看不到的地方），检查几何、标注（不能残留旧标注）、以及标题栏/技术要求/客户标识/剖面线是否原样保留。
- H2 把交付的 DWG 用 AutoCAD 转成 DXF 后，与原图逐个实体比对：84 个孔的孔心和孔径、其余实体一个不多一个不少、两个 Ø40 标注、修订文字、AutoCAD 审核、原文件未被覆盖，以及打印用的图纸布局。
- H3 逐张检查几何、标注、零件号和材料文字；无效的两行必须没有出图且在报告里说明。
- 所有 H1 最终图纸和 H3 的 60 张图都经过 AutoCAD 审核；H1 最终图纸用 AutoCAD 出图目视检查。

评分中有两处是我根据实际情况修正的，如实说明：
1. H3 第一次评分时，一半运行的"孔标注"被判失败。检查后发现 Agent 用的是"6×Ø12"引线注释，这是标注成组孔的标准写法，是评分脚本过严。改为接受后全部通过。
2. H2 第一次评分时只看模型空间，B 组被判"缺标注、缺修订文字"，A 组全对。检查后发现这张图有一个打印用的图纸布局（Base Plate），里面有零件按 0.325 比例的完整副本和标题块。B 组把孔改在了模型空间**和**图纸布局两处，标注和文字放在图纸布局上（并把标注的比例因子设为 1/0.325，使显示值为 Ø40）；A 组只改了模型空间，打印出来的图纸上仍然是 Ø10.2 和 Ø25。改为同时检查图纸布局后，结论反转。

### 看到的行为

- **撤回**：A 组 3 次都先查 `history` / `list_checkpoints`，用 `get_diff` 找出第 2 轮之前的孔径，再只改这几个实体。B 组从第 1 轮起就自觉地每轮先备份（`part.round2.before.dxf` 等）、保存修改脚本和核对记录，第 4 轮靠这些备份找回旧值，并逐字节核对其余内容未变。B 等于自己重造了 AgentCAD 的检查点和操作日志，多花的时间主要在这里。
- **H2 的图纸布局**：B 组能直接用 ezdxf 浏览整个文件，发现了图纸布局里的零件副本；A 组通过 AgentCAD 只看得到模型空间（`read_drawing`、`inspect_entities` 都只报告模型空间），根本不知道还有一张图纸要改。这不是 Agent 的错，是 AgentCAD 的覆盖范围问题，此前的[实测报告](trials-report.md)已把"只处理模型空间"列为已知限制，这次在真实任务里造成了错误交付。
- **主动性**：B 组在 H1 里主动指出"加宽后客户标识与零件重叠"（这是我出题时的布置疏漏；因为题目要求不许动其他内容，两组都没改）。
- **版面**：H1 终稿两组都正确；B 组 1 次的 Ø30 引线文字与"4X Ø10"文字相互重叠，A 组的 Ø30 标注画在孔内，没有冲突。

## 怎么看

1. **AgentCAD 的速度优势是稳定的**（2–3.5 倍），原因是 Agent 不用自己写脚本、读回、核对，也不用自己维护备份和记录。
2. **但抽象层会让 Agent "看不见"**。B 组能处理 H2，靠的是能直接访问整个文件；AgentCAD 没覆盖到的部分，Agent 既改不了也意识不到。在真实图纸上，这比慢更致命：A 组 3 次都交付了一张自相矛盾的图纸，而且自己报告"全部通过"。
3. **正确性上，在这些任务里 AgentCAD 没有体现出优势**；它的价值目前主要是速度、可追溯的历史和更少的手工步骤。

## 对 AgentCAD 的改进建议（按优先级）

1. **支持图纸空间布局**：读取时报告所有布局及其内容；操作和校验都能指定布局；提醒"图纸布局里有模型的副本"这类情况。真实图纸几乎都要打印，这是第一优先级。
2. **提供受控的"脚本出口"**：允许 Agent 提交一段 ezdxf 脚本处理工具没覆盖到的情况，但脚本在事务里运行（先建检查点、失败整体回滚、改完自动校验并记录 diff）。这样能保留 B 组的灵活性，又不丢 A 组的速度和可追溯性。
3. **校验时报告"未检查的部分"**：例如"图纸布局 Base Plate 中有 84 个圆未被检查"，避免 Agent 在看不见的地方报告"全部通过"。

## 改进之后（2026-10-28）

按上面的建议改了 AgentCAD，然后只重跑 H2 的 A 组（其余任务的结果不受影响，没有重跑）：

- **v2：支持图纸空间布局。** `read_drawing` 列出各布局及其内容；所有操作都有 `layout` 参数；handle 和标签在所有布局中查找；`validate_drawing` 可以检查指定布局，并对没有检查到的布局给出 `LAYOUT_NOT_VALIDATED` 警告；标注值按显示值（含 DIMLFAC）比较。另外新增默认关闭的 `run_script`（脚本在独立进程中运行，按事务提交）。
- **v3：补上 v2 重跑时暴露的两个卡点。** 三次运行里 Agent 都想改图纸上标注的比例因子（让 0.325 比例的图纸显示 Ø40），但 `modify` 不支持标注；也都想直接审核导出的 DWG，但 `autocad_audit` 只收 DXF。现在标注操作有 `length_factor` 参数，`modify` 可以改标注的文字、字高和比例因子，`autocad_audit` 接受 DWG。

| H2（真实 DWG 改图） | 正确率 | 平均耗时 | 输入 / 输出 token | 每次的工具错误 |
|---|---|---|---|---|
| A v1（只有模型空间） | 0/3 | 2.8 分钟 | 74 万 / 0.4 万 | 0–2 |
| A v2（支持布局） | **3/3** | 5.4 分钟 | 166 万 / 0.9 万 | 4–5 |
| A v3（再补两个卡点） | **3/3** | **3.4 分钟** | 114 万 / 0.5 万 | 1–3 |
| B（直接写代码） | 3/3 | 9.7 分钟 | 110 万 / 1.4 万 | 0（写脚本，无工具调用） |

v3 的三次运行都把图纸布局上的孔改对了，标注显示 Ø40，修订文字齐全，其余实体一个不多一个不少，AutoCAD 审核 0 错误。剩下的工具错误主要是"先试了 `run_script`，被告知未开启"（3/3 次），其次是两次被 `strict` 校验拒绝后自行改正。v3 的数据未计入上文的主结果表，原始记录分别在 `examples/trials/hard/v1/`、`v2/` 和当前的 `runs/A/`。

结论更新：补上覆盖范围之后，AgentCAD 在这道真实图纸题上也做对了，并且比直接写代码快约 3 倍、模型输出少约 60%；输入 token 与直接写代码相当。

## 第二组：三道常见日常任务（2026-10-28）

同样的两组、同样各跑 3 次，换成三道日常工作里最常见的活：

- **H4 整理图纸**：外协厂发来的安装板图，所有对象都在 0 层、颜色单独指定，还有一个重复的孔、两条和外框重合的线、两条长度为 0 的线和三个空图层。要求按公司的四层标准（OUTLINE / CENTER / DIM / TEXT，颜色、线型、线宽都规定）整理，对象属性改成随层，删掉重复对象、零长线和空图层，几何与文字不变。
- **H5 补全尺寸**：一块只有图形的支架板（两个 Ø14 孔、40×12 腰形槽、10×45° 倒角），要求标注到能加工：总长总高、孔径孔距与定位、槽的长宽与位置、倒角；必须是真正的尺寸对象、数值正确、不重复、文字不压线。
- **H6 出图布局**：模型空间里有一张标好尺寸的 300×160 底板，要求新建 A3 布局，画内外图框和标题栏（图名、图号、比例、材料），开一个 1:2 的视口显示整个零件，不能超出内框、不能压住标题栏。AgentCAD 的操作目录里**没有**新建布局和视口的操作，这道题专门用来看缺功能时会怎样。

评分仍然只用 ezdxf 中立地读结果文件。三道题的评分程序都先验证过：原始底图判为不合格，手写的标准答案判为全部通过。H5 和 H6 的成品还用 AutoCAD 出图人工看过（`examples/trials/hard/png/H5/`、`png/H6/`）。

| 任务 | A 组（AgentCAD） | B 组（直接写代码） |
|---|---|---|
| H4 整理图纸 | **3/3**，1.5 分钟，输入 40 万 / 输出 0.28 万 token | 3/3，3.5 分钟，28 万 / 0.58 万 |
| H5 补全尺寸 | **3/3**，2.5 分钟，52 万 / 0.43 万 | 3/3，6.5 分钟，62 万 / 0.96 万 |
| H6 出图布局（脚本出口关闭，默认） | **0/3**，1.5 分钟 | 3/3，3.6 分钟，20 万 / 0.62 万 |
| H6 出图布局（脚本出口打开） | **3/3**，2.1 分钟，45 万 / 0.46 万 | （同上） |
| H6 出图布局（新增布局/视口操作，脚本出口关闭） | **3/3**，2.5 分钟，63 万 / 0.50 万 | （同上） |

看到的情况：

1. **工具覆盖到的任务，两组都全对，A 组快 2–2.6 倍，输出 token 约少一半。** H5 两组画出来的图几乎一样：尺寸齐全、数值正确、布置整齐。A 组每次 1–2 个工具错误，都按结构化错误自行改正。
2. **工具没覆盖到的任务（H6），默认配置下 A 组做不了，但失败得很干净。** 三次都报告"没有创建布局/视口的操作，`run_script` 未开启"，原图一个字节没动，没有假装完成。
3. **打开脚本出口后 A 组 3/3**，比 B 组快约 1.7 倍：常规部分仍用工具，只有建布局、设纸张、开视口这一步交给 `run_script`，这一步同样走检查点、diff 和校验。
4. **两组共同漏掉的问题**：底图的标注字高是按 1:1 定的（3.5 mm），在 1:2 视口里只有 1.75 mm，打印出来太小。两组都没有发现，评分程序也没检查。这类"打印后是否看得清"的问题，目前只能靠人看出图结果。

结论：常用操作走工具、缺的部分走受控脚本，这个组合在这组任务上全部做对，而且始终比直接写代码快。但脚本出口默认关闭，所以默认配置下仍应尽快把"新建布局 / 视口"做成正式操作；另外校验器可以增加"按视口比例换算后的打印字高"检查。H6 脚本关闭时的原始记录在 `examples/trials/hard/h6_noscript/`，脚本打开时的在 `h6_scripts/`。

### 补上布局/视口操作之后

按上面的结论新增了两个正式操作和一项检查，然后在**脚本出口关闭**（默认配置）下重跑 H6 的 A 组 3 次：

- `create_layout`：新建打印布局，纸张 A0–A4（横/竖）或自定义尺寸，图纸空间单位为 mm。
- `add_viewport`：在布局里按固定比例开视口，默认显示模型空间的全部内容；返回视口在纸上的位置、实际显示的模型范围，以及是否完整显示了模型。
- 校验器新增 `PRINTED_TEXT_TOO_SMALL`（警告）：把模型里的文字和标注文字按各视口比例换算成纸上字高，图纸空间文字直接比较，小于 2.5 mm 就提醒。

结果 **3/3**，平均 2.5 分钟，比直接写代码（3.6 分钟）快约 1.4 倍，AutoCAD 出图检查无误（`examples/trials/hard/png/H6/A_ops/`）。和打开脚本出口相比慢 0.4 分钟、输入 token 多一些，因为图框、标题栏要逐项用操作画。三次运行都还是先试了一下 `run_script`，被告知未开启后改用正式操作，每次多花 1 次调用。

新检查起了作用：三次都收到了"1:2 下标注字高只有 1.75 mm"的警告，并在报告里写明了这个不足。它们都没有去改标注，因为任务要求"不要改动模型空间里的零件和尺寸"，这个取舍是合理的，问题也交代给了人。上一轮两组都完全没有意识到这个问题。
