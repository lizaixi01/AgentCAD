# 换一个 Agent 再比一次：Claude Code（Opus 5.5）

之前所有对比实验都用 Codex CLI 做 Agent（[comparison-code-vs-agentcad.md](comparison-code-vs-agentcad.md)、[comparison-hard-tasks.md](comparison-hard-tasks.md)）。这次把 Agent 换成 Claude Code，把同样的 12 道题再跑一遍，看结论是否只对 Codex 成立。

## 怎么跑的

| | A 组：AgentCAD | B 组：直接写代码 |
|---|---|---|
| Agent | Claude Code 2.1.308 无头模式（`claude -p`），模型 claude-opus-5-5，推理强度 high | 同左 |
| 能用什么 | 关掉全部内置工具（`--tools ""`），只允许 AgentCAD 的 MCP 工具 | 读写文件工具，加上只能运行指定 Python 的 Bash（`Bash(<python> *)`）；工作区在仓库外，Python 里只有 ezdxf 1.4.5 |
| 其它权限 | 会弹权限确认的操作一律自动拒绝（`--permission-prompts none`） | 同左；工作区内的编辑自动接受 |
| 任务和评分 | 和 Codex 那轮完全相同：同一份任务说明、同一套中立评分程序 | 同左 |

T1–T6 每组各跑 1 次；H1–H6 每组各跑 3 次（H1 每次 5 轮，每轮一个新会话），一共 72 个会话。启动器见 [examples/trials/agents.py](../examples/trials/agents.py)，Claude Code 的记录在 `examples/trials/runs_cc*/` 和 `examples/trials/hard/runs_cc/`，评分在 `grades_cc.json`。

第 1 轮的 H2–H6 和 H1、T2–T6 同时在跑（最多 7 个会话并发，抢 AutoCAD 和网络），有两次运行明显偏慢（A 组 H6 第 1 次 17 分钟，B 组 H6 第 1 次 11 分钟）。下表的耗时用**中位数**，均值附在后面。B 组 H2 第 2 次因为 API 连接中断（`ECONNRESET`）重跑过一次。

## 看到了什么

1. **正确率：A 组 42 次运行全对；B 组错了 1 次，错在"撤回"上。** H1 第 4 轮要求"撤回第 2 轮的孔径修改"，每轮是新会话，不记得之前做过什么。A 组三次都从操作历史和检查点里查到第 2 轮之前是 Ø10，改了回去。B 组第 1 次自己记了笔记，但只记了第 3 轮；图纸里已经看不出原来的孔径，它没有乱猜，而是保持原样并请人提供原值。处理方式是诚实的，但结果不对，第 5 轮也跟着错。Codex 那轮两组都是 3/3，所以这次是 Claude Code 在 B 组里恰好没留全记录。这正是内置操作历史的用处：不依赖 Agent 自觉记笔记。
2. **速度：AgentCAD 仍然在大多数题上更快，但领先幅度比 Codex 那轮小。** Claude Code 直接写代码比 Codex 快得多（例如 H1 从 18.3 降到 12.9 分钟，H5 从 6.5 降到 2.5 分钟），所以差距缩小到 1.2–1.9 倍。**H3 批量出图反过来了**：B 组写一个脚本循环出 12 张图，2.9 分钟；A 组每张图都要调用工具、校验，3.8 分钟。
3. **费用：AgentCAD 在多数题上更贵。** 除 H3 外，A 组输出 token 少 25–60%；但输入 token 是 B 组的 1.9–3.8 倍（只有 H1 少 12%），因为操作目录和每次调用返回的结构化结果都进上下文。只有 H1（5 轮改图）A 组更便宜；H3 A 组是 B 组的 3 倍，输出 token 也多 80%。
4. **头号摩擦是我们自己的：`list_operations` 太大。** 不带参数时返回约 96K 字符，超过 Claude Code 单次工具结果的上限，**36 个 A 组会话里有 34 个第一次调用就失败**，之后改成按类别查询（每次多 2–4 次调用）。Codex 没有这个上限，所以上一轮没暴露。T1 慢、A 组输入 token 多，都和它有关。
5. **其它错误**：5 次试用未开启的 `run_script`；3 次想直接改尺寸标注的定义点（`modify` 不支持）。都按结构化错误自行改正。B 组有 1 次用 heredoc 写临时脚本被权限拦下，改用文件工具。

## 结论

- 换成 Claude Code 后，"AgentCAD 和直接写代码正确率相当"仍然成立，而且在需要追溯历史的多轮修改上 AgentCAD 更稳（3/3 对 2/3）。
- "AgentCAD 更快"在多数题上仍然成立，但幅度依 Agent 而定：写代码越快的 Agent，差距越小；批量重复的活，写一个脚本循环反而更快。
- "AgentCAD 更省"不成立：按美元算，多数题更贵。主要原因是操作目录太大和返回结果太长，这是可以改的。

## 建议的改进

1. `list_operations` 默认只返回操作名、类别和一句话说明（约 3–4K 字符），参数详情按需查询（`ops=[...]` 或 `category=...`）。预计能消掉 34/36 次首调失败，并明显降低 A 组输入 token。
2. 精简 `apply_operations` / `inspect_entities` 的默认返回（只给句柄和摘要，详情按需）。
3. 批量任务给一个"同一套操作套用到多张图"的入口，或者在文档里建议批量场景开启 `run_script`。

## 改进 1 之后：操作目录改成"渐进式披露"（2026-10-29）

按上面第 1 条改了 `list_operations`：不带参数时只返回操作名、类别、一句话说明和参数名（`*` 表示必填），约 9.5K 字符；要类型、单位、默认值和取值范围时，用 `ops=[...]` 查指定操作，或用 `category=...` 查一类，`detail=true` 才返回全部（原来的约 96K 字符）。

然后只重跑 A 组（B 组不用我们的代码，结果不变），条件和上一轮完全相同：T1–T6 各 1 次、H1–H6 各 3 次，共 36 个会话。为了不受同一目录里另一个会话正在开发的改动影响，这次 MCP 服务器跑在一份独立的代码快照上（上次提交 eecbacc，只加了这一处改动）。原来的 A 组记录保存在 `runs_cc/v1/` 和 `hard/runs_cc/v1/`。

结果：**24 组运行全部正确**（T1–T6 6/6，H1–H6 每题 3/3）。

|---|---|---|---|---|

看到的变化：

1. **首调失败消失了**，工具错误从每次 0.3–6.3 个降到 0–1.3 个；剩下的主要是 H2 里想直接改尺寸标注定义点（`modify` 不支持）和 H1 里试用未开启的 `run_script`。
2. **更快了**：每道题都比改前快 9–47%；除 H3 批量出图外，全部比直接写代码快（1.6–3.1 倍）。
3. **更省了**：每道题便宜 5–26%。H1、H4 已经比直接写代码便宜；H5、H6、T1–T6 只贵 $0.04–0.06；H2、H3 仍然明显更贵。
4. **输入 token 仍是主要差距**：单会话任务降了 4–40%，但仍是 B 组的 1.8–2.3 倍；H1 没有降，因为每轮都是新会话，每轮都要重新读目录、查历史和看图。下一步应该把同样的渐进式披露用到 `inspect_entities`、`apply_operations` 和 `validate_drawing` 的返回上：默认只给摘要和句柄，细节按需查询。
