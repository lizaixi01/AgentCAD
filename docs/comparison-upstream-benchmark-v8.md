目录 token 使用上游 ratio/v1 估算，排除服务 instructions，不代表真实模型计费 token。

worker，验证 `A:end → B:run`；随后通过新的 MCP 进程读取其保存结果。这一处不声称
纯公开工具就能制造该内部竞态，其余被计分 CAD 工作通过公开 MCP 工具完成。

## 建筑、机械质量门槛没有用自评分替代

两张成品 DXF 额外交给未修改的上游 `run_critique(focus=None)` 和
`DrawingValidator`，使用原版 `combine` 权重。要求仍然是零 critique 问题、质量分 ≥90。
同时检查 oracle 前后文件哈希相同，证明它只读，没有替产品修改成品。

建筑质量分为 100；机械为 92，critique 均为零。机械剩下一条原版 validator warning：
BOM 中 `ISO 4014 M12x60` 被当作疑似伪尺寸文字，扣 8 分。该警告保留在报告中，没有过滤。
AgentCAD 自带的 `quality_score` 也保留，但与上游分数分列，不能混为同一种量尺。
上游部分领域规则依赖它自己的 XDATA；因此这些通用检查之外，适配器还要求产品自身
从保存文件重建房间/零件/BOM 等语义，并用独立数值核对，不能仅凭原版零问题宣称全部领域语义已被它识别。

## 独立审查后的最终复测

[PR #36](https://github.com/lizaixi01/AgentCAD/pull/36) 的独立审查在固定题例之外
找到了四个反例，均已在 `514de729d3da4eadbf75097a7365c87dee453613` 修复：

1. 房间可见 TEXT 被改坏时，原记录和面积仍正确不能视为干净图纸；现在检查显示文字。
2. 最后一个零件删除后，旧 BOM 行和气泡仍要被判为悬空；现在双向比较行/实体集合。
3. ARC 的不存在象限、bulge 曲线的弦不能当作尺寸依附几何；现在使用真实有限弧段。
4. 凹多边形凹口可以跨过整个包围盒；现在按边界交点分段检查完整边缘的包含关系。

两位独立审查者分别发布了[行为复审](https://github.com/lizaixi01/AgentCAD/pull/36#issuecomment-6517951719)
和[评测复审](https://github.com/lizaixi01/AgentCAD/pull/36#issuecomment-6517956764)，确认原反例不再发生。
这些问题也说明固定矩阵满分不代表不存在矩阵以外的缺陷。

干净修复提交的全套复测仍为 **v8 31/31、v2 10/10**；建筑/机械原版质量分
仍为 **100/92**。仓库回归为 **416 passed、73 skipped**，新增 7 个正反例覆盖上述边界。
本轮复用此前同日、同固定上游提交的参考结果，没有把参考结果说成又重跑了一次。

新测量单独保存在 [recheck/](../examples/autocad_benchmark/results/2026-10-30-v8/recheck/)，
含 `agentcad.json`、新哈希清单、成品预览及 `evidence.zip`。第一轮 `c2cd0f5` 的报告、
339 份归档证据及参考结果逐字节保留；旧的 `945e6c6` 基线也未改写。

## 结论的实际边界

这是确定性合成任务的能力验收，不是同模型完成任务率或速度排行榜。AgentCAD 每项
启动 MCP 服务并做磁盘事务，参考实现多为进程内调用；耗时只作诊断，不能由此比较模型效率。

建筑当前限定毫米、正交墙、无内部岛的房间和英文表格；机械限定所述旋转轮廓与通孔剖面，
不是通用装配求解器；外来工厂图的管线/电缆是初步直角路径估算，语言及符号识别仍有限。
详细契约及拒绝条件见 [工程工作流说明](engineering-workflows.md)。满分不会消除这些范围限制。
