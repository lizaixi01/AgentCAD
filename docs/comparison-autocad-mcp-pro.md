# AgentCAD 与 AutoCAD MCP Pro 的同题对比

日期：2026-10-29。目的：比较相同 Agent 在两套 CAD MCP 工具上的任务完成情况、耗时和失败恢复。实验脚本及复现说明见 [pro_comparison](../examples/trials/pro_comparison/README.md)。

## 条件

- AgentCAD：提交 `51333f9773a077d2a573c3683fc310a1e6113452`；AutoCAD MCP Pro：1.7.0，提交 `58a05ddfc34a9832c626e82cd88ecdce8e16a62a`。
- 两组均使用 Codex CLI 0.163.0、gpt-6.1-sol、high 推理强度；每组每题计划运行三次。两侧在同一机器同时运行，任务对依次运行，故时间包含并发资源竞争。
- 共用一份底图的逐字节副本、同一任务说明及评分程序；只在工具入门提示中分别说明 `list_operations` 和 `search_tools` / `call_tool` 的使用方式。会话不得运行命令或使用其他插件。
- AgentCAD：工作区限制、脚本关闭；Pro：ezdxf 后端、工作区白名单、按需搜索模式、`EZDXF_UNDO_DEPTH=5`。主实验 Pro 安装默认依赖，没有 Pillow 和 matplotlib，因此无法无头截图。
- AgentCAD 使用 ezdxf 1.4.5 / mcp 1.30.0；Pro 的锁定环境使用 ezdxf 1.4.4 / mcp 1.29.0 / fastmcp 3.4.5。两者采用各自安装的依赖版本。
- H1 每一轮均启动全新的 Codex 和 MCP 进程，逐轮保存独立快照。H4 / H5 单会话完成。评分器只读取生成的 DXF，不调用任一产品的验证器；它自身依赖 ezdxf，不能替代工程师目视审核。

## 任务结果

| 任务 | AgentCAD 通过 | Pro 通过 | AgentCAD 中位耗时 | Pro 中位耗时 | MCP 调用中位数 A / Pro |
|---|---:|---:|---:|---:|---:|
| H4 图层清理 | 3/3 | 3/3 | 57.24 秒 | 104.13 秒 | 11 / 124 |
| H5 补全尺寸 | 3/3 | 3/3 | 110.60 秒 | 192.52 秒 | 10 / 89 |
| H1 五轮修订 | 3/3 | 0/3 | 223.59 秒 | 473.59 秒* | 45 / 239 |

H1 的 `*` 是 Pro 停止时已经花费的时间，不是成功完成任务所需的时间。三次均在第四轮找不到第二轮前的孔径；它没有猜测，保留当前图纸并请求旧值。第五轮继续完成标题栏修改，但由于第四轮未撤回，最终图纸仍未达到整套任务要求。AgentCAD 三次均从持久化历史中恢复旧孔径，并保留其他轮次的修改。

H4 / H5 的三次输入 token 中位数分别为 AgentCAD 314,778 / 349,649，Pro 525,971 / 840,308；其中缓存输入中位数分别为 AgentCAD 272,000 / 309,632，Pro 482,560 / 801,152。缓存输入与未缓存输入的费用不同，不能用总输入 token 直接推断费用倍数。

第三组 H1 原运行中，Pro 的模型请求返回容量不足，AgentCAD 的后续模型请求因网络断开超时；两者均作为基础设施中断排除。原日志保留，用完全相同的底图及同一模型重跑整对。重跑的单会话超时为 360 秒，原实验为 900 秒；所有有效重跑均在 360 秒内结束。`grades.json` 保留中断结果，`retry_grades.json` 保存重跑结果，汇总时只计 `infrastructure_ok=true`。

## 故障注入

对同一条直线的独立副本，先移动，再尝试删除不存在的对象：

- AgentCAD 的单图 `apply_operations` 返回失败，磁盘原图字节未变。
- Pro 的 `cad_batch` 默认 `on_error=stop` 明确报告不保证原子性；第一步保留，随后保存后图纸中的直线已移动。将 `on_error` 设为 `rollback` 时，同一失败场景恢复了原几何。这是两种有文档说明的策略，不能把默认行为描述为未报告的故障。
- 完成一次移动并关闭服务，再启动新进程：AgentCAD 的持久检查点能恢复原位置；Pro 即使开启五步无头 undo，重启后也返回没有可撤销的操作。此项未测试用户主动保存独立备份的工作流。
- 为两边都设置工作区范围后，读取范围外文件均被拒绝。

每项故障注入执行两次，观察结果一致；它们仅证明本次场景。汇总见 [probe_summary.json](../examples/trials/pro_comparison/probe_summary.json)。

## 限制

样本少、任务来自本项目既有试题，不能代表所有 CAD 工作流或所有 Agent。没有比较 DWG 原生读写、实时 AutoCAD、三维建模或行业库。自动评分覆盖指定几何、尺寸和保留项，不能证明图纸完全符合制图规范或视觉排版要求。Pro 的其他配置、人工备份流程和后续版本可能得到不同结果。

## Pro 目录与截图配置的补充对照

安装 Pro 的 `[pdf]` extra 后，已用 MCP 确认无头截图返回图像。然后用与主实验字节相同的 H4 底图，分别对搜索模式和完整工具目录各运行一次；每次仍与 AgentCAD 同机配对。两次的 Pro 设置均为 ezdxf、工作区白名单、undo 深度 5，且截图组件可用。

| Pro 模式 | 任务通过 | 耗时 | MCP 调用 | 输入 token（缓存输入） |
|---|---:|---:|---:|---:|
| 按需搜索 | 是 | 106.33 秒 | 188 | 535,975（497,280） |
| 完整目录 | 否 | 106.48 秒 | 27 | 921,155（867,968） |

完整目录模式的结果中，22 个实体的线宽均为 DXF 的 `DEFAULT=-3`，而任务要求随层 `BYLAYER=-1`；模型的最终报告却称线宽均已随层。其余评分项通过。搜索模式这一次通过全部 H4 检查。完整目录模式可以通过批处理减少外部调用，因此调用次数不等同于底层操作次数。每种模式只有一次，不能据此推断稳定性，也不能把失败任务的耗时当成成功交付时间比较。
