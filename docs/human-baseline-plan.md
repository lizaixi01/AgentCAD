# 人类基准实验设计：熟练工程师 vs Agent + AgentCAD

日期：2026-10-30。状态：**设计稿，尚未执行**。

## 为什么要做

到目前为止的对比（[comparison-hard-tasks.md](comparison-hard-tasks.md)、[comparison-autocad-mcp-pro.md](comparison-autocad-mcp-pro.md) 等）都是"同一个 Agent 换不同工具"，回答的是"Agent 用 AgentCAD 是否比用别的工具好"。工程师真正关心的是另一个问题：**这件活交给 Agent，比我自己用熟悉的软件做，到底省不省事、出不出错？** 没有这个对比，"AI 在 CAD 里能起多大作用"只能靠猜。

本实验要回答三个问题：

1. 在哪些任务上，工程师自己动手的时间能明显减少？在哪些任务上反而更慢？
2. Agent 交付物的缺陷比人多还是少？是哪类缺陷？
3. 算上写需求、检查、返工的时间，Agent 的真实收益是多少？

我们预计 Agent 在一部分任务上会输。输的结果和赢的一样要发表，它告诉我们该补哪块。

## 两组

| | 人类组 | Agent 组 |
|---|---|---|
| 执行者 | 熟练工程师，日常用 CAD 工作 ≥3 年 | Claude Code 和 Codex，各自接入 AgentCAD MCP |
| 软件 | **自己平时用的软件和环境**：AutoCAD / 中望 / SolidWorks / Inventor / Creo 等，可以用自己的模板、LISP、宏、设计表 | 只能用 AgentCAD 的工具（与以往试验相同的设置） |
| 人数 / 次数 | 至少 3 人，每人每题做 1 次 | 每个 Agent 每题 3 次 |
| 监督 | 无 | 两种模式，分别计分（见下） |

人类组用自己的工具，因为这才是要被比较的真实生产力。如果工程师有现成的 LISP 能一键完成某题，那就是事实，应该算进去。

Agent 组分两种模式：

- **无人值守**：把工单原文发出去，中间不帮忙。与以往试验相同。
- **有人监督**：一位工程师（不是本实验的人类组成员）把工单原文发给 Agent，看结果，发现问题可以用自然语言要求修改，最多 3 轮，然后声明完成。这相当于人类组交付前的自查，是现实中的用法。**这位工程师的每一分钟都计入"人工时间"。**

为了不让监督者变成"带着答案的评审"：

- 监督者在全部运行结束前看不到验收清单、评分脚本的输出，也看不到其他运行的评分结果，只能凭自己的工程判断提意见。
- 监督者发给 Agent 的每一条消息原文发表。
- 监督者要监督几十次运行，会逐渐熟悉 Agent 的常见错误。这在现实中也会发生，但会让后面的运行更占便宜。对策：题目和 Agent 的顺序轮换，报告里按运行顺序列出数据，让读者能看出有没有这种趋势。

## 任务

尽量复用已有的题目、输入文件和评分脚本（[examples/trials/hard/](../examples/trials/hard/)），只为人类组补上必要的材料。任务刻意覆盖两类：预计 Agent 占优的批量、重复类工作，和预计人占优的单件、判断类工作。

| 编号 | 任务 | 来源 | 输入 / 交付 | 预计 |
|---|---|---|---|---|
| HB1 | 设计变更传播：一处改动（板宽 120→150、安装孔 Ø10→Ø12）要同步到一套 8 张相关图纸（零件图、装配图、图内明细表、标题栏版本号和修订记录） | **新建**，以 H1 的安装板为种子 | 8 张 DXF / 同名交付 | Agent 占优 |
| HB2 | 外协图纸整理：按公司图层标准整理，删除重复对象 | H4 | DXF / DXF | Agent 占优 |
| HB3 | 按参数表批量出图：12 行法兰参数，其中 2 行几何上不成立 | H3 | 参数表 / 10 张 DXF + 报告 | Agent 占优 |
| HB4 | 真实 DWG 改图：改两种孔径、加标注、加修订文字，其余不动，包括打印用的图纸布局 | H2 | DWG / DWG | 不确定 |
| HB5 | 给支架板标全尺寸，让车间能加工 | H5 | DXF / DXF | 人占优 |
| HB6 | 出 A3 图纸：图框、标题栏、1:2 视口 | H6 | DXF / DXF | 不确定 |
| HB7 | 按一张带约 20 个尺寸的二维图建三维参数化零件（法兰轮毂），然后改两个参数（法兰 Ø160、孔 Ø40），其余特征随动 | **新建**，参照 [docs/assets/part3d/](assets/part3d/) | 二维图 PDF / 原生模型 + STEP | 人占优 |
| HB8 | 小改：一张图改一个尺寸、加一行技术要求 | H1 第 1 轮，另加一行技术要求 | DXF / DXF | 人占优（测 Agent 的固定开销） |

格式上的说明：

- 人类组的 2D 交付可以是 DWG 或 DXF，评分前统一用 AutoCAD 转成 DXF。
- HB7 人类组交付自己软件的原生模型加 STEP，Agent 组交付 `.FCStd` 加 STEP。只按 STEP 评几何；"改参数后其余特征随动"这一项，由评审在各自软件里现场演示或看录屏判定。
- HB4 的输入是 AutoCAD 自带的样例图纸。它不进仓库（见 [.gitignore](../.gitignore) 的说明）。用 AutoCAD 的参与者从自己的安装目录取用；不用 AutoCAD 的参与者由组织者在仓库之外单独提供。
- HB7 需要会用三维参数化软件的人。如果凑不够 3 人，就按实际人数做，在报告里注明。

## 任务描述

- 每题一份书面工单，写法像真实的工作安排，由一位不参与实验的工程师按现有 `tasks/*.md` 改写。人类组和 Agent 组拿到**同一份文字**。
- 正式开始前，用一位工程师做预试，只确认工单没有歧义，不给预试者看评分细则。工单改过之后冻结。
- 人类组可以就工单内容提问，回答写进记录，并同步给 Agent 组的监督者（Agent 组无人值守模式不能提问，这是该模式本身的限制，在结果中注明）。
- 每题有时限：取预试用时的 3 倍，不少于 30 分钟、不超过 4 小时，正式开始前写进工单。超时未交付算"未通过"，用时按时限记。

## 交付与返工

两组走同一个流程：

1. 执行者声明完成，这是**首次交付**。有人监督模式下，首次交付是监督者在最多 3 轮修改之后声明的完成，监督的时间已经计入人工时间。
2. 评分（机器检查 + 盲审）给出缺陷清单，原样交回执行者。Agent 组由监督者把清单原文转给 Agent（无人值守模式也由一位操作者转发，转发和检查的时间计入人工时间）。
3. 最多 2 轮返工，每轮之后重新评分。
4. 2 轮返工后仍有严重缺陷的，记为**最终未通过**，用时照实记录。

## 记录什么

| 指标 | 人类组 | Agent 组 |
|---|---|---|
| **人工时间**（主指标） | 从打开工单到最终交付，包括返工 | 读工单、发给 Agent、检查结果、写修改意见、转发缺陷清单的时间总和，包括返工 |
| 首次交付前的人工时间 | 从打开工单到首次交付 | 同上，截止到首次交付 |
| 总耗时 | 同人工时间 | 从发出工单到最终交付 |
| 首次交付合格率 | 首次交付是否没有严重缺陷 | 同左 |
| 最终合格率 | 返工后是否没有严重缺陷 | 同左 |
| 缺陷数（按严重程度） | 每次交付分别统计 | 同左 |
| 返工轮次和时间 | 最多 2 轮 | 同左 |
| 成本 | 人工时间 × 时薪（时薪作为参数，由使用者代入） | token 费用 + 人工时间 × 时薪 |

计时方式：人类组录屏，或在固定检查点手动记时间戳；Agent 组用运行器的日志时间。监督者的时间同样录屏或记时间戳。

人工时间是主指标。工程师在意的不是 Agent 跑了几分钟，而是自己被占用了几分钟；Agent 在后台跑的时候，人可以做别的事。

## 评分

两层，都不采信执行者的自报：

1. **机器检查**：沿用 [grade_hard.py](../examples/trials/hard/grade_hard.py) 和 [grade_hard2.py](../examples/trials/hard/grade_hard2.py)（H4–H6）的做法：DWG 先用 AutoCAD 转成 DXF，然后只用 ezdxf 读图（3D 只读 STEP），不用 AgentCAD 自己的验证器。按每题的验收清单逐项判定。HB1、HB7 的清单和脚本需要新写。
2. **盲审**：所有交付物用同一套出图流程渲染成 PNG，去掉文件名和作者信息、打乱顺序，交给第三位工程师按制图规范评审。
   - 模型空间用 [render_png.py](../examples/trials/render_png.py)（AutoCAD 出图）。
   - 图纸布局用 [render_layout_png.py](../examples/trials/render_layout_png.py)。HB4 的打印布局（Base Plate）和 HB6 的 A3 布局都必须出图，因为 HB4 已知的失败方式就出在布局上。这个脚本目前只出名为 "A3" 的布局，需要加一个布局名参数。
   - HB7 的 STEP 由同一个程序按固定的几个视角渲染，需要新写一个脚本（例如用 FreeCAD 读 STEP）。
   - 各家软件的标注样式和模板可能让评审认出是谁做的，所以盲审只能做到"尽量盲"。评审给每张图写下自己猜的作者（人 / Agent），报告里公布猜中率。

缺陷分三级：

- **严重**：按图加工会做错零件，例如尺寸值与几何不符、改错了孔、漏改了打印用的图纸布局、该拒绝的参数行出了图。
- **一般**：车间需要回来问，例如漏标尺寸、同一尺寸重复标、明细表与图不一致。
- **轻微**：只影响规范和美观，例如文字压线、图层或线型不对。

一个交付物有任何严重缺陷，就算"未通过"。

## 事先登记的判断标准

为了不在看到结果后挪动标准，先写下来：

- 每个 Agent（Claude Code、Codex）、每种模式分别判定，不合并。缺陷用"每次交付的严重缺陷数"比较，因为两组的次数不同（Agent 每题 3 次，人类组每题至少 3 人）。
- **Agent 在某题上"有用"**：人工时间（含返工）的中位数 ≤ 人类组的 50%，最终合格率不低于人类组，并且首次交付的每次严重缺陷数不多于人类组。
- **Agent 在某题上"不划算"**：人工时间中位数 ≥ 人类组，或最终合格率低于人类组。
- 介于两者之间的如实报告，不归类。
- 最终未通过的运行，人工时间照实计入中位数（超时的按时限计），不剔除。
- 预计 HB1–HB3 "有用"，HB5、HB7、HB8 "不划算"。预计落空的情况在报告中单独列出。

样本量小（每题 3 名工程师），所以只报每个人和每次运行的原始数据和中位数，不做显著性检验，也不把结果外推成"AI 能替代百分之几的工作"。

## 威胁与对策

| 问题 | 对策 |
|---|---|
| 工程师之间水平差异大 | 报告每个人的数据，不只报平均；记录每人的软件和年限 |
| 熟悉 / 学习效应 | 每人每题只做一次；题目顺序在人之间轮换 |
| 工单措辞对某一方有利 | 由第三方工程师写，预试只查歧义 |
| 监督者水平影响 Agent 组成绩 | 监督者固定一人，看不到评分细则和结果，每条消息原文发表 |
| 监督者越做越熟 | 顺序轮换，按运行顺序报告数据 |
| 人类组用 DWG、Agent 组用 DXF | 交付前统一转换，按同一标准评分；HB4 两组都必须交 DWG |
| 评审偏向 | 盲审，公布评审猜作者的猜中率；机器检查优先于主观判断 |
| 题目偏向 2D 和板件 | 如实说明覆盖范围；装配、公差分析、强度不在本轮范围内 |

## 执行步骤

1. **准备**（项目内部可以完成）：新建 HB1 的 8 张图纸和 HB7 的二维图，写验收清单和评分脚本，给 `render_layout_png.py` 加布局名参数，写 STEP 渲染脚本，给所有题目写工单；先让 Agent 跑一遍，确认评分脚本能区分对错。这一遍的结果不计入正式数据，监督者不参与。
2. **招募**（由项目负责人决定）：至少 3 名工程师和 1 名盲审，最好 2D、3D 各有擅长的人；确定报酬和时薪参数。
3. **预试**：1 名工程师做 HB2 和 HB8，校准时限和计时方式，修正工单。
4. **正式执行**：人类组按轮换顺序做完 8 题；Agent 组两种模式各跑 3 次。
5. **评分和报告**：写成 `docs/comparison-human-baseline.md`，格式与已有对比报告一致，原始记录放在 `examples/trials/human/`（录屏不进仓库，只放时间戳和交付文件）。

## 本轮不覆盖

装配和运动干涉、公差分析、强度计算、工艺和成本判断。这些是工程师工作中最难的部分，也是 AgentCAD 目前完全不涉及的部分（见 [limitations-roadmap.md](limitations-roadmap.md)）。本实验只回答"重复性的出图和改图工作能省多少"，不回答"AI 能不能做设计"。
